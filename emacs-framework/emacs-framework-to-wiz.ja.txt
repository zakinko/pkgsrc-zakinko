1. 枠組み
=========

modules.mk、mk/pbulk/pbulk-index.mk、それと Emacs package 自身への小さな
差分が四つ (version.mk、buildlink3.mk、新しく入れる site-start.el)。何を
するかを、いただいた三点の順に、そのあと建てて分かった分を。

版の選び方は pyversion.mk のもので、前回間違えていた所も含めて。
EMACS_VERSION_REQD は受けるか断るか。無ければ EMACS_TYPE は既定で、
それを受けない package は自分が受ける先頭の版に落ちる。package が書いた
EMACS_VERSIONS_ACCEPTED を書いた順に歩いて。（前回「出来た」と書いたのは
意図であって code ではありませんでした。loop が歩いていたのは modules.mk
の一覧で、mailcrypt が emacs20 を先頭に書いても emacs31 が選ばれていた。
いまは package の側を歩き、並べ替えは他に決め手が無い所でだけ答えを
動かします。）devel/apel が立てていて誰も読まなかった
EMACS_VERSIONS_INCOMPATIBLE は、pyversion.mk が同等物を引くのと同じ形で
引きます。依存の pattern は PKGNAME_REQD から読み戻し、これで連鎖が自分と
食い違わなくなる。www/emacs-w3m は emacs20 を受け devel/apel は受けない
ので、EMACS_TYPE=emacs20 だと emacs-w3m が emacs20-apel を求め、apel は
emacs29-apel として建ち、誰も理由を言わなかった。いまは apel の所で、版と
package と受ける一覧を名指しして止まります。

lisp は share/emacs/<version>/site-lisp へ。Emacs は元からそこと一段目の
sub directory を探すので、何も教えなくてよい。建つ物を全部入れ、持って
いる .elc 390 個を全部並べて、どれも load-path 上に在ることを見ました。
share/emacs/site-lisp はまだ隣に在るので、まだ動いていない package には
影響しない。

名前は版を持ちます。emacs29-apel、emacs30-apel、版だけ。一つの Emacs の
nox build と X build は互いに衝突し、同じ site-lisp を共有し、木の中で
二つに別の file 一覧を入れる package は一つも無い（それを見る条件 87 個
を全部読みました）ので、emacs30-foo 一つでどちらにも効き、pbulk は二つで
なく一つ作る。devel/apel は 6 項目が 3 に、textproc/xslide は 11 が 6 に。
依存はどちらの build でも満たす形に書き、pkg_add がそれを効かせる。
emacs30-nox11 だけが入った箱で、同じ binary package がこの一行で入ったり
断られたりします。

  @pkgdep emacs30>=30.1<31              pkg_add: no pkg found, sorry.
  @pkgdep {emacs30-nox11,emacs30}>=...  入る

X build を断る package — EMACS_VERSIONS_INCOMPATIBLE にそう書く物 — が
例外で、emacs30-nox11-foo と名乗り、依存はその build に固定するので、
動かせない Emacs の上に binary package が乗ることはない。
EMACS_TYPE=emacs30nox で devel/apel だと

  いまの modules.mk   apel-10.8.0.20201107nb2、EMACS_VERSIONS_INCOMPATIBLE=
                      emacs30nox を言っても同じ
  行を読む形          emacs30-apel        既定
                      emacs29-apel        emacs30nox は駄目と言うと
                      emacs30-nox11-apel  emacs30 は駄目と言うと

XEmacs は系列で割れたまま、xemacs214- と xemacs215-。今日はどちらも
xemacs-。package は EMACS_VERSIONS_ACCEPTED に対の両側を書かなくてよく
なりますが、書いてある一覧もそのまま効きます。

pbulk は三行と言ったのが四行です。class を _PBULK_MULTI にも名指しする
必要があって、loop が歩くのはその一覧。書いた一覧でなく絞った一覧が要る
のも、python が _PYTHON_VERSIONS_ACCEPTED を取るのと同じ理由。それで
devel/apel は

  PKGNAME=emacs30-apel-10.8.0.20201107nb2
  PKGNAME=emacs29-apel-10.8.0.20201107nb2
  PKGNAME=emacs31-apel-10.8.0.20201107nb2

既定が先頭。emacs20 しか受けない devel/pcl-cvs は一行、modules.mk を
読まない devel/gmake は変わらず。

そのあと、建てて分かった三つ。どれも Emacs が一つしか入らない間は見え
なかった物です。

EMACS_BIN が ${PREFIX}/bin/${_EMACS_FLAVOR} だったので、emacs29 向けに
建てても bin/emacs を持っている Emacs、30.2 で byte-compile していた。
いまは GNU Emacs では版付きの binary。XEmacs は素の名前のままで、これは
わざとです。21.5 は bin/xemacs-21.5-b36 を入れますが 21.4 は版付きの
実行 file を一つも入れず、bin/xemacs-21.4.25-<hash>.dmp だけ。名前を
当て推量しないために 21.4 を建てて確かめました。

nox の version.mk は X11 の双子を写して一行変えた物で、写しが腐って
いた。editors/emacs29-nox11/version.mk は 29.1 と言い、package は 29.4 を
建てるので、lisp は share/emacs/29.1/site-lisp へ行き、build の load path
は無い directory を指していた。いまは nox の file が双子を include して
違う所だけ立て、各 buildlink3.mk が三度目に書いていた ABI の下限は
version.mk に移したので、版は Emacs ごとに一箇所にしか書かれない。

info と etc も lisp と一緒に版の下へ。名前に版が入ると、一つの package
の二つの build は同じ file を書く二つの package で、pkg_add が二つ目を
止めるので。

  pkg_add: emacs29-skk-17.1nb2: conflicting PLIST with
           emacs30-skk-17.1nb2: info/skk.info

inputmethod/skk を各 Emacs で一度ずつ建てた物です。87 個のうち 30 個が
info を入れる。etc は share/emacs/<version>/etc で、使う二つの package
が build 時に path を焼き込むので安全。info は枠組み独自の path でなく
PKGINFODIR を通しました。modules.mk が版が決まった所でそれを
share/emacs/<version>/info に立てると、pkgsrc が info file に既にして
いる事 — plist-info.awk の info/ の正規化、gnu-configure.mk が渡す
--infodir、dir file — が package に何も言わずに付いてくる。PLIST が
info/foo.info と綴っていても正しいまま。最初は逆の形、独自の path で
PLIST 11 個を ${EMACS_INFOPREFIX}/ に書き換える形を試して、あらゆる向きで
悪かった。mail/mailutils は --infodir=${PREFIX}/${PKGINFODIR} を渡すので
古い場所に書き PLIST は新しい場所を見る、devel/cqual はその逆。PKGINFODIR
ならどちらも一行も要らない。

info には lisp と違って受け口が要ります。Emacs は Info-default-
directory-list で探し、それは configure 時の自分の --infodir から作られ、
実行時の手掛かりは INFOPATH だけ。そこで Emacs package が site-lisp の隣に
二行の site-start.el を入れます。

  (add-to-list (quote Info-default-directory-list)
    (expand-file-name "../info" (file-name-directory load-file-name)) t)

これで skk は share/emacs/30.2/info/skk.info を入れ、C-h i が見つける。
この file が無いと見つからない。site-start.el という名前を取ってしまう
のは管理者が欲しがるかもしれない名前で、一行の site-start.el が読む
site-start.d ならそれを空けておける。訊かずに木の慣習を発明したくなかった
のでそのままにしてあります。info の変更で建てた package と、まだ測って
いない物は 4 に。

もう一つ自分の物。build 用の EMACSLOADPATH がまだ古い共有 site-lisp を
指していて、他の elisp package に対して byte-compile する物は "Cannot open
load file" で止まった。建てないと出なかった。EMACS_LISPPREFIX 自体は最初
から正しかったので。

この部が出来ないのは、二つの Emacs を並べること。editors/emacs29 と
editors/emacs30 は互いに衝突を宣言せず、file を 93 共有する — bin/emacs、
bin/ctags、bin/etags、bin/emacsclient、bin/ebrowse、include/emacs-module.h、
info 66、share の下 15 — ので pkg_add が bin/ctags で二つ目を止める。
その 93 を手で外すと二つは並んで動き、emacs 29.4 と emacs 30.2、上の
測定は全部その形でやりました。python313 のように binary に版を付けるのは
訊かれた三点より大きい変更で、していません。それをするまで、版付きの
名前で買える物の天井を決めてもいます。bulk は全部の版を建てられ、名前は
どの Emacs 向けかを記録するけれど、二つを一つの箱に置くことはまだ出来
ない。

prefix の代価が二つ、決めるより前に置きます。package を脆弱性一覧の
届く範囲から外す。pkg_admin audit-pkg は flim-1.14.2 に CAN-2004-0422 を
報告し、emacs30-flim-1.14.2 には何も言わない — xemacs-flim-1.14.2 にも
なので、今日の xemacs- package で既にそうなっている。勧告は列挙で覆えて、
{,emacs30-}flim<1.14.3、一覧 30234 項目のうち 3778 は既に brace で始まる。
いま一覧に在る物は影響を受けない。Emacs 自身でなく elisp package への
勧告は flim<1.14.3 だけで、pkgsrc は 1.14.9 なので。それと、改名された
package を名指す CONFLICTS の pattern が当たらなくなる。これは直しの側に
在ります。そこで噛まれたので。

差分: modules.mk (1.42 に対して 402 行)、pbulk-index.mk (20)、Emacs
package への四つ。

3. 適応 — 今日は正しく、prefix が入ると間違う物
==============================================
